# Commit comparison (Orqeto Dev)

The **Commit** context offers **Current state** (the existing staged, unstaged, and untracked report) and **Compare commits**. Comparison is read-only: it does not checkout a revision, move HEAD, change branches, create a commit, or modify project files.

Select an initial and a final commit using the dropdowns. Each option displays an abbreviated hash, commit subject, author, and local date/time. The complete hash identifies the revision internally and is included in the generated context. History is read from all reachable Git references in pages of 100; the search input filters the commits already loaded, and **Load more** continues pagination. **Refresh history** starts again from the current repository state.

**Generate** computes the direct Git tree diff `initial → final`, not a merge-base comparison and not a list of intervening commits. Swapping the selected revisions reverses the comparison. The diff is restricted to the selected project directory when the selected root is a subfolder of a Git repository. The report includes both full hashes, subjects, author names, author dates/times, changed-file count, added/deleted line counts, and the patch text. Binary-file changes count as changed files but do not contribute numeric line counts. No change is reported when the two trees are identical within the selected project.

The backend validates full 40/64-character commit hashes, re-reads each commit at comparison time, uses bounded Git execution without external diff or textconv tools, and applies existing Git-diff and unstructured-text secret redaction before returning results. A diff larger than 8 MiB is rejected rather than silently truncated. Extremely large histories have a bounded pagination offset. The generated context is archived under the existing Commit context-history kind; it can be copied, downloaded as `.txt`, and is auto-copied when the existing generated-report setting is enabled. Copy/Download are available only while the displayed pair matches the generated report. Switching between Current state and Compare commits never applies the diff.

Regression coverage is provided by `scripts/business-rules/git-commit-comparison.test.mts` and `src-tauri/src/git_context/commit_compare_tests.rs` (including forward/reverse diffs and an isolated Git working tree). Run Type Check, ESLint, and `npm test` after applying the incremental ZIP.
